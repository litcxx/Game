# Game Client

Thin browser renderer for the authoritative [game server](../server). The server
owns all state; the client sends the player's intent and draws the snapshots it
receives. Built with **TypeScript + PixiJS + protobuf-es** over a WebSocket.

> **Status: MVP, work in progress.** The full MVP loop works: spawn, movement,
> territory capture, area-attack combat, and death/respawn. The client renders
> the territory grid, players (with HP bars), and — for your own player — the
> attack-range ring and a cooldown bar.

## Tech stack

- **TypeScript** (type-checked with `tsc --noEmit`)
- **Vite** — dev server and bundler
- **PixiJS** — 2D WebGL/canvas rendering
- **protobuf-es** (`@bufbuild/protobuf`) — wire protocol, generated by **buf**
  (`@bufbuild/buf` + `protoc-gen-es`) from `../protocol/game/v1/protocol.proto`
- **tsx** — runs the headless end-to-end smoke scripts

## How it works

One WebSocket **binary frame = one Protobuf message** (`ClientMessage` out,
`ServerMessage` in) — the same framing the server uses.

- **`src/net/client.ts`** — `GameClient`: opens the WebSocket, sends `Hello`, and
  encodes/decodes messages. `sendSpawn` / `sendInput(moveX, moveY, capturing,
  attack)` carry the player's intent; incoming frames are decoded and handed to a
  callback.
- **`src/render/scene.ts`** — `Scene`: draws the territory grid (owned cells
  tinted by faction, in-progress captures by progress), a dot per player with an
  HP bar, and for your own player the attack-range ring plus a cooldown bar.
- **`src/input/keyboard.ts`** — WASD / arrows → movement direction, **E** →
  capture; fires only when the intent changes.
- **`src/main.ts`** — wires it together: applies `Welcome` / `MapState` /
  `Roster` / `Snapshot` to the scene, drives attack on left-mouse, and spawns /
  respawns on click.

## Controls

| Input | Action |
|-------|--------|
| **WASD** / arrows | Move |
| Hold **E** | Capture the cell under you |
| Hold **left mouse** | Area attack around you (fires each cooldown) |
| **Click** a cell | Spawn / respawn there (only while not alive) |
| Keys **1–N** | Pick faction (before spawning) |

## Prerequisites

- **Node ≥ 22** (Vite 8; the smoke scripts use Node's global `WebSocket`)
- A running game server (default `ws://localhost:27998/`, set in `src/main.ts`)

## Getting started

```bash
npm install
npm run generate     # protobuf-es -> src/gen (git-ignored)
npm run dev          # Vite dev server; open the printed URL
```

Start the server first (see [`../server`](../server)). Other scripts:

```bash
npm run typecheck    # tsc --noEmit
npm run build        # generate + typecheck + vite build (-> dist/)
```

## Headless smoke tests

`scripts/` holds end-to-end checks that talk to a running server over a real
WebSocket and print a `VERDICT`. Start the server, then:

```bash
npx tsx scripts/smoke.ts          # connect + Hello/Welcome
npx tsx scripts/m2_smoke.ts       # spawn + movement
npx tsx scripts/capture_smoke.ts  # hold E -> capture a cell
npx tsx scripts/combat_smoke.ts   # area attack -> hit -> death
```

## Layout

```
../protocol/game/v1/protocol.proto   wire protocol (shared with the server)
src/net/       GameClient — WebSocket transport + protobuf encode/decode
src/render/    Scene — PixiJS rendering (grid, players, HP/attack/cooldown)
src/input/     keyboard — movement + capture intent
src/gen/       generated protobuf-es code (git-ignored; run `npm run generate`)
scripts/       headless end-to-end smoke tests (tsx)
docs/          sequence diagrams + the design concept
```
