**Goal:** Add the block — a short window in which the player takes no damage
from any attack, on its own cooldown — and make melee swings and blocks
visible to everyone.

**Architecture:** Block is a new data-driven ability kind (`block`, bar slot 3)
with its own timer, separate from the shared attack cooldown. The server
activates blocks before resolving attacks each tick, and the single damage
choke point `apply_damage()` turns a hit on a blocking player into a blocked
hit (no damage). Every ability use is announced with an `AbilityEvent`; the
client turns those events (and blocked hits) into short visual effects,
delayed like remote players' interpolation so they line up with what is drawn.

**Tech Stack:** C++23 server (GoogleTest, protobuf), TypeScript + PixiJS 8 +
protobuf-es client, `tsx` check/smoke scripts.

**Spec:** the "Design" section below (the user confirmed the understanding on
2026-09-28 and asked to proceed).

## Design

- **What the user asked for.** Block has its own cooldown, separate from melee
  and ranged (block, switch, attack at once). Its cooldown equals melee's
  (0.75 s); it lasts 0.15 s; all values come from the config. During the block
  any incoming attack — melee or projectile — deals no damage. Melee swings and
  blocks must be visible to other players, as projectiles already are.
- **Confirmed assumptions.** Block is bar slot 3 (key 3, used with LMB like the
  attacks; holding repeats it when ready). A projectile that meets a block is
  spent without damage. The block covers all directions; moving while blocking
  is allowed. A block and an attack in the same tick: the block already counts.
- **Config.** `abilities[]` gains `{ "id": 3, "kind": "block", "name": "Блок",
  "cooldown_ticks": 45, "duration_ticks": 9 }`. For `block`, `damage`/`range`
  are optional (0); `duration_ticks > 0` is required. Melee and projectile keep
  requiring theirs.
- **Server.** Player: `block_until_tick` (blocking while `tick <
  block_until_tick`), `block_ready_tick`, `block_cooldown_ticks`. Tick order:
  inputs → movement → index → **blocks** → attacks → projectiles → capture →
  snapshot. `activate_blocks()` starts a block for every alive player holding
  attack with a block ability selected and its block timer ready; it never
  touches the attack cooldown, and `resolve_attacks()` ignores block
  abilities. `apply_damage()` on a blocking target records
  `HitEvent{damage: 0, blocked: true}` and changes nothing else (a projectile is
  still spent by it).
- **Events.** `GameEvent.ability = AbilityEvent{player_id, ability_id}` for
  every use — melee swing (even when nothing is hit), block, projectile launch.
  `HitEvent.blocked` marks a hit stopped by a block.
- **Self state.** `SelfState.block_ready_tick` and `block_cooldown_ticks` (the
  attack pair stays as is).
- **Client.** Slot 3 shows a shield icon; every bar slot shows its cooldown
  (attack cooldown on attack slots, block cooldown on the block slot) as a
  dark overlay. With the block slot active, the ring is a small circle around
  the token carrying the block's cooldown arc. Effects, for every player:
  melee **swing** — a ring expanding to the melee range in the faction colour
  (~220 ms); **shield** — a bright ring around the token for the block's
  duration; **blocked** — a white burst plus a rising "БЛОК" (~700 ms) on the
  defender. Remote players' effects start `INTERP_DELAY` after arrival (they are
  drawn 100 ms in the past); the local player's start on arrival.

## Global Constraints

- Server builds warning-free under the strict flags (`-Werror`, `-Wconversion`, …), ASan/UBSan preset.
- No `auto [..] = co_await ...` binding owned results (GCC 16.1 leak).
- Proto: enum 0 = UNSPECIFIED; hot fields keep numbers 1–15; comments in Russian like the rest of the file.
- Client hardcodes no rule numbers; everything comes from Welcome.
- Melee, ranged, capture and prediction behaviour stays as it is; all existing tests and smokes stay green.

## Review Focus

- Block pressed in the same tick as an incoming swing → blocked (blocks resolve before attacks).
- The block ends exactly at `start + duration`: a hit on that tick lands.
- Projectile reaching a blocking target → spent, no damage, not passing through to someone behind.
- Blocking must not start or reset the shared attack cooldown, and attacking must not touch the block timer.
- A melee swing that hits nobody is still announced (the visual must not depend on a hit).
